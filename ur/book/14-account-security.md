# 14. اکاؤنٹ اور معلومات کی حفاظت

پیمانہ: پیسہ اور ذاتی معلومات۔ جب کوئی اور آپ کے اکاؤنٹ میں login ہوتا ہے، تو سب سے پہلے پیسہ ضائع ہوتا ہے۔ دوسری فریق آپ کے اکاؤنٹ کو آپ کی contact list میں لوگوں کو scam کرنے کے لیے بھی استعمال کرے گا۔ آپ کی identity بھی effectively چھن جاتی ہے۔

### 1. email، payment، اور social accounts کے لیے two-factor authentication آن کریں؛ phone pop-up confirmation کو ترجیح دیں، SMS verification codes کو ثانوی option کے طور پر
<!-- cost-tag: money=0 time=little willpower=none benefit=large metric=money -->
- لاگت: مفت۔ ہر اکاؤنٹ کو ایک بار set up کریں؛ ہر setup میں دو سے تین منٹ۔
- آسان الفاظ میں: Two-factor authentication کا مطلب یہ ہے کہ login کے وقت، password کے علاوہ، آپ ایک بار پھر confirm کریں کہ واقعی آپ ہی ہیں۔ Phone pop-up کا طریقہ جسے آپ tap کر کے confirm کرتے ہیں phishing-پر مبنی account takeovers کا 90% سے زیادہ روکتا ہے۔ "آخری بار کہاں login کیا"، "backup email کیا ہے" جیسے پرانے طریقوں پر انحصار کرنے سے صرف تقریباً 10% phishing takeovers روکتے ہیں۔
- فائدہ: Google نے 350,000 actual account-takeover attempts (account hijacking بھی کہا جاتا ہے) کو شمار کیا۔ ایک category device-based verification ہے، جیسے phone pop-up جو آپ سے confirm کروائے، یا security key plug کرنا۔ یہ category "phishing-پر مبنی hijacking attempts کا 94% سے زیادہ اور automated hijacking attempts کا 100%" block کرتی ہے۔ Phishing کا مطلب آپ کو fake site پر password enter کرنے کے لیے دھوکہ دینا ہے؛ automated کا مطلب machines کی طرف سے leaked passwords کو bulk میں try کرنا ہے۔ دوسری category question-based verification ہے، جیسے آخری بار کہاں login کیا یا backup email کیا ہے پوچھنا۔ یہ category "phishing hijackings کا صرف 10% تک اور automated hijackings کا 73%" block کرتی ہے
- ثبوت کا درجہ: A
- ماخذ: Doerfler P, Thomas K, Marincenko M, et al. (2019). Evaluating Login Challenges as a Defense Against Account Takeover. The World Wide Web Conference (WWW '19). <https://doi.org/10.1145/3308558.3313481>
- نوٹ: اسی study میں پایا گیا کہ ایسی verification اکثر real user کو بھی lock کر دیتی ہے۔ 52% genuine users پہلی کوشش پر login نہیں کر سکے، مگر بالآخر 97% اندر آ گئے۔ یہ پہلے آپ کے email کے لیے آن کریں، کیونکہ بیشتر دیگر accounts password recover کرنے کے لیے email استعمال کر سکتے ہیں۔

### 2. آپ کا email password منفرد ہونا چاہیے اور کسی بھی website پر reuse نہ ہو
<!-- cost-tag: money=0 time=little willpower=some benefit=large metric=money -->
- لاگت: مفت۔ Password manager استعمال کریں اور آپ کو یاد رکھنے کی ضرورت نہیں۔ مشکل حصہ ہر جگہ ایک password استعمال کرنے کی پرانی عادت توڑنا ہے۔
- آسان الفاظ میں: دیگر sites سے چوری ہوئے passwords براہ راست آپ کے email پر try کیے جائیں گے۔ ایک بار email login ہو جائے، تو password recovery کے لیے email استعمال کرنے والا ہر اکاؤنٹ اس کے ساتھ ضائع ہو جاتا ہے۔ تو آپ کا email password منفرد ہونا چاہیے اور کہیں اور کبھی استعمال نہ ہو۔
- فائدہ: Leaked accounts اور passwords کو ایک ایک کر کے login کے لیے try کرنا credential stuffing کہلاتا ہے، اور یہ سب سے آسان attack طریقہ ہے؛ آپ کا email بھی اس طرح try کیا جائے گا۔ ایک بار email login ہو جائے، تو password recovery کے لیے اس کا استعمال کرنے والے تمام accounts ایک ساتھ ضائع ہو جاتے ہیں۔ US Cybersecurity and Infrastructure Security Agency مشورہ دیتی ہے: ہر اکاؤنٹ کے لیے الگ strong password استعمال کریں، کم از کم 16 characters، password manager میں store
- ثبوت کا درجہ: C
- ماخذ: US CISA. Use Strong Passwords. <https://www.cisa.gov/secure-our-world/use-strong-passwords>
- نوٹ: اگر یاد نہیں رکھ سکتے، تو اپنے browser کے built-in password manager استعمال کریں۔ یہ ہر site کا password آپ کے لیے یاد رکھتا ہے، ہر جگہ ایک password استعمال کرنے سے کہیں بہتر۔ Passwords WeChat favorites یا memo apps میں store نہ کریں۔

### 3. Phone lock-screen password set کریں؛ SIM card پر PIN set کریں
<!-- cost-tag: money=0 time=little willpower=none benefit=large metric=money -->
- لاگت: مفت۔ Lock-screen password اور PIN ایک بار each set کریں۔
- آسان الفاظ میں: SIM card phone کے اندر کا چھوٹا card ہے؛ SMS verification codes اس کے ذریعے receive ہوتی ہیں۔ اگر phone گم ہو جائے، تو جو اٹھا لے وہ اس card کو نکال کر دوسرے phone میں ڈال دے گا، verification codes receive کرے گا، اور آپ کے accounts ایک ایک کر کے reset کر دے گا۔ Card پر PIN set کریں، اور جب card دوسرے phone میں move ہو، تو startup پر PIN درج کرنا پڑے گا — یہ راستہ cut ہو جاتا ہے۔
- فائدہ: Phone گم ہونے کے بعد، جو اسے ڈھونڈتا ہے اس کا سب سے تیز راستہ SIM card کو دوسرے phone میں ڈال کر آپ کی SMS verification codes receive کرنا ہے۔ Verification codes کے ساتھ، وہ آپ کے accounts ایک ایک کر کے reset کر سکتے ہیں۔ اگر SIM card کے پاس PIN ہو، تو اسے دوسرے phone میں move کرنے کے لیے startup پر password درج کرنا پڑتا ہے، تو ڈھونڈنے والا اسے verification codes receive کرنے کے لیے استعمال نہیں کر سکتا
- ثبوت کا درجہ: C
- ماخذ: مصنف کا تجربہ، کوئی براہ راست ادب نہیں
- نوٹ: PIN phone کی settings میں "SIM card lock" کے تحت set ہوتا ہے۔ Default factory code عموماً 1234 یا 0000 ہوتا ہے۔ مسلسل تین غلط entries کے بعد، آپ کو carrier کی طرف سے PUK code استعمال کر کے unlock کرنا پڑتا ہے۔ تو set کرنے کے بعد، code کو پہلے کاغذ پر لکھ لیں۔

### 4. اگر آپ کا phone گم ہو جائے، تو اس ترتیب پر عمل کریں: SIM card lost report کریں، remotely lock کریں، passwords بدلیں، police کو report کریں، bank cards freeze کریں
<!-- cost-tag: money=0 time=little willpower=none benefit=large metric=money -->
- لاگت: مفت۔ پورا sequence درجن منٹوں کا۔
- آسان الفاظ میں: ترتیب رفتار سے زیادہ اہم ہے۔ پہلا step، SIM card lost report کریں، اور verification codes کی lifeline cut ہو جاتی ہے۔ اگلا، phone remotely lock کریں، پھر computer استعمال کر کے email اور payment passwords بدلیں، پھر receipt کے لیے police کو report کریں، اور آخر میں ضرورت کے مطابق bank cards freeze کریں۔ اگر phone آپ کے پاس نہیں، تو کسی اور کا phone borrow کر کے carrier کی customer service کو کال کریں اور loss report کریں۔
- فائدہ: ترتیب رفتار سے زیادہ اہم ہے۔ پہلا step، SIM card lost report کریں، اور دیگر آپ کی verification codes receive نہیں کر سکتے۔ دوسرا، phone remotely lock کریں اور اس کے contents wipe کریں۔ تیسرا، email اور payment passwords computer سے بدلیں۔ چوتھا، police کو report کریں اور receipt حاصل کریں۔ آخر میں، ضرورت کے مطابق bank cards freeze کریں۔ US Federal Communications Commission بھی مشورہ دیتی ہے: اگر آپ کو صرف گم ہونے کا شک ہو، تب بھی remotely lock کریں۔ اگر چوری ہوئی ہو، فوراً report کریں، model اور IMEI serial نمبر (phone کا identity number) دیں، اور فوراً carrier کو notify کریں
- ثبوت کا درجہ: C
- ماخذ: US FCC. Protect Your Smart Device. <https://www.fcc.gov/consumers/guides/protect-your-mobile-device>; step order is author experience; for ID card replacement, see Section 7; for impersonation loans, see Section 8's entry on credit reports
- نوٹ: تینوں carriers کے customer service numbers پہلے سے لکھ لیں: China Mobile 10086، China Unicom 10010، China Telecom 10000۔ نیز note کر لیں کہ آپ کا اپنا phone نمبر کس شہر میں register ہوا تھا — customer service پوچھے گی۔ آپ کسی اور کے phone سے customer service کو کال کر کے loss report کر سکتے ہیں۔

### 5. چوری شدہ card کے لیے، پہلے report اور freeze کریں، پھر police جائیں، پھر bank سے ادائیگی کا مطالبہ کریں: "آپ نے خود swipe کیا" ثابت کرنا bank کی ذمہ داری ہے
<!-- cost-tag: money=0 time=little willpower=some benefit=large metric=money -->
- لاگت: مفت۔ اگر card پر غیر معمولی activity دیکھیں، تو فوراً report یا freeze کریں۔ Police report، loss report، اور bank سے transaction notifications رکھیں۔ اگر card اب بھی آپ کے پاس ہے، تو قریب میں ایک چھوٹی balance inquiry یا deposit کر کے record چھوڑیں جو یہ دکھائے کہ real card اس وقت آپ کے ہاتھ میں تھی۔ مشکل حصہ پہلے customer service سے بحث کرنے کے جذبے کو روکنا ہے — پہلے freeze۔
- آسان الفاظ میں: چوری شدہ card کے لیے، آپ کو یہ ثابت کرنے کی ضرورت نہیں کہ "یہ میں نے swipe نہیں کیا"۔ بالعکس، bank کو ثبوت produce کرنا چاہیے کہ یہ transaction آپ نے ذاتی طور پر کیا؛ اگر نہیں کر سکتا، تو آپ کو compensation دے۔ شرط یہ ہے کہ notice کرتے ہی آپ report اور freeze کریں۔ delay کریں، تو بعد میں جمع ہونے والے اضافی نقصانات آپ کو اٹھانے پڑیں گے۔
- فائدہ: Supreme People's Court کی provisions "ثبوت کون فراہم کرتا ہے" کو separate کرتی ہیں۔ آپ دعویٰ کرتے ہیں کہ یہ counterfeit-card یا online-card fraud ہے؛ آپ کو پہلے ثبوت فراہم کرنا ہوگا۔ Counterfeit-card fraud کا مطلب card copy ہو کر استعمال ہونا ہے۔ ثبوت میں شامل ہیں: موثر قانونی دستاویزات، transaction کے وقت real card کہاں تھی، transaction کہاں ہوئی۔ نیز account transaction تفصیلات، transaction notifications، police reports، loss reports، وغیرہ۔ **بالعکس، اگر issuing bank یا non-bank payment institution (third-party payment) دعویٰ کرے کہ transaction cardholder کی طرف سے یا اس کی authorization سے کی گئی، تو انہیں ثبوت produce کرنا ہوگا**۔ آپ bank کو notify کرنے کے بعد، اگر bank وقت پر verify نہیں کر سکتی، یا وقت پر transaction slips اور surveillance footage provide اور preserve نہیں کر سکتی، اور اس کے نتیجے میں ثبوت حاصل نہیں ہو سکتے، تو ثبوت produce نہ کرنے کے نتائج bank اٹھاتی ہے۔ Finding قائم ہونے کے بعد: debit card (savings card) holders کے لیے، issuing bank سے چوری شدہ deposit principal اور interest آپ کو ادا کروائی جا سکتی ہے، اور نقصانات کا compensation دلوایا جا سکتا ہے۔ Credit card holders کے لیے، deduct کیا گیا overdraft principal، interest، اور penalties refund کیے جا سکتے ہیں، اور bank سے نقصانات کا compensation دلوایا جا سکتا ہے؛ اگر bank بالعکس آپ سے overdraft ادا کرنے کا مطالبہ کرے، تو عدالت support نہیں کرے گی۔ آپ issuing bank سے appropriate adverse credit records فوراً revoke کروا سکتے ہیں (ملکی سطح پر، 25 مئی 2021 سے نافذ)
- ثبوت کا درجہ: A
- ماخذ: Supreme People's Court (2021). Provisions on Several Issues Concerning the Trial of Civil Disputes over Bank Cards (Articles 4, 5, 7, 14, 15). <https://www.court.gov.cn/fabu/xiangqing/304771.html>
- نوٹ: دو صورتیں ہیں جن میں آپ خود liability اٹھاتے ہیں۔ پہلا، آپ نے bank card، password، یا verification code safeguard نہیں کیا، اور آپ کی غلطی تھی (اصل متن "proper custody کا فرض پورا نہیں کیا اور غلطی میں تھا" ہے)، liability غلطی کے تناسب سے۔ تو password کسی کو نہ بتائیں، verification codes دوسروں کو forward نہ کریں (دیکھیں اندراج 1، two-factor verification کے لیے phone pop-up کو ترجیح دیں)۔ دوسرا، اگر آپ نے وقت پر report نہیں کیا اور نقصانات بڑھنے دیے، تو اضافی حصہ آپ خود اٹھاتے ہیں۔ تو پہلا step ہمیشہ report اور freeze کرنا ہے؛ customer service سے پہلے بحث نہ کریں۔ Third-party payment institutions بھی اس rules set کے تحت آتے ہیں۔ اگر ان کے promotional مواد "advance compensation" بتاتے ہیں اور وہ مخصوص، واضح commitments کرتے ہیں، تو آپ مطالبہ کر سکتے ہیں کہ وہ پہلے ادا کریں۔ اگر آپ کو دھوکہ دے کر خود پیسہ transfer کرایا گیا، تو مختلف طریقہ کار لاگو ہوتا ہے؛ دیکھیں سیکشن 8، اندراج 2 (اگر آپ کو دھوکہ ہونے کا پتہ چلے، تو فوراً 110 یا 96110 پر کال کر کے payment stop کروائیں)۔

### 6. وقتاً فوقتاً اپنے اکاؤنٹ کے login devices اور authorized apps چیک کریں؛ جو اب استعمال میں نہیں انہیں remove کریں
<!-- cost-tag: money=0 time=little willpower=some benefit=medium metric=money -->
- لاگت: مفت۔ ہر check میں چند منٹ۔ مشکل حصہ یہ ہے کہ کوئی آپ کو یاد نہیں دلاتا؛ آپ کو خود یاد رکھنا ہے۔
- آسان الفاظ میں: "Login devices" وہ phones اور computers ہیں جو اب بھی آپ کا اکاؤنٹ استعمال کر سکتے ہیں۔ Account چور اکثر act کرنے سے پہلے کچھ عرصہ خاموش رہتے ہیں۔ اگر list میں کوئی غیر familiar device نظر آئے، یا لمبے عرصے سے unused software اب بھی آپ کے اکاؤنٹ سے connect ہو، تو تمام sessions log out کریں اور password بدل دیں۔
- فائدہ: Account چوری اکثر فوراً act نہیں ہوتی؛ دوسری طرف کچھ عرصہ خاموش رہتی ہے۔ آپ کے اکاؤنٹ میں login device list وہ phones اور computers record کرتا ہے جو اب بھی اس اکاؤنٹ کا استعمال کر سکتے ہیں۔ Authorized-app list دیگر software record کرتا ہے جسے آپ نے اس اکاؤنٹ کے ساتھ login کی اجازت دی ہے۔ List میں غیر familiar devices، اور لمبے عرصے سے unused third-party software، سب سے آسان پہچاننے کے نشان ہیں
- ثبوت کا درجہ: C
- ماخذ: مصنف کا تجربہ، کوئی براہ راست ادب نہیں
- نوٹ: WeChat، Alipay، email، Apple accounts، اور Android accounts سب میں یہ entry point ہے۔ اگر کوئی غیر familiar device ملے، تو all sessions log out پر click کریں، پھر password بدل دیں۔

### 7. ایک app استعمال کرنے کے لیے "سب کو agree" پر click نہ کریں: non-essential معلومات کے لیے، consent سے انکار کو آپ سے service محروم کرنے کے لیے استعمال نہیں کیا جا سکتا
<!-- cost-tag: money=0 time=little willpower=some benefit=medium metric=freedom -->
- لاگت: مفت۔ مشکل حصہ "سب کو agree" click کرنے کے جذبے کو روکنا ہے۔
- آسان الفاظ میں: جب app آپ سے معلومات مانگے، اگر وہ service فراہم کرنے کے لیے ضروری نہیں، تو آپ کا consent سے انکار آپ کو service محروم کرنے کی وجہ نہیں بن سکتا۔ جو وہ collect کر سکتی ہے وہ بھی ضرورت تک محدود ہے۔ Map app آپ کا location مانگنا ضروری ہے؛ flashlight آپ کے contacts مانگنا ضروری نہیں۔
- فائدہ: قانون واضح طور پر دو اصول بیان کرتا ہے۔ پہلا، اس بنیاد پر کہ فرد consent نہیں کرتا یا consent واپس لے لیتا ہے، product یا service فراہم کرنے سے انکار منع ہے، سوائے جہاں ایسی معلومات process کرنا service فراہم کرنے کے لیے ضروری ہو۔ دوسرا، collection processing مقصد حاصل کرنے کے لیے ضروری minimum scope تک محدود ہوگی؛ صرف جو ضروری ہو وہ collect کیا جا سکتا ہے
- ثبوت کا درجہ: A
- ماخذ: Standing Committee of the National People's Congress (2021). Personal Information Protection Law.
