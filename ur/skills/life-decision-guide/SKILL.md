# زندگی کے فیصلے: ہاؤ ٹو لائیو بیٹر سے تلاش کر کے جواب دیں

## یہ سکل کیا کرتی ہے

جب کوئی زندگی کی مخصوص بات کے بارے میں پوچھتا ہے، پہلے ہاؤ ٹو لائیو بیٹر میں متعلقہ اندراجات تلاش کریں، پھر کتاب کے اکاؤنٹنگ انداز میں ترتیب دے کر جواب دیں۔

**تلاش نہ ہو تو جواب مت دیں۔** جواب میں ہر عدد، ہر قانونی شق، ہر نتیجہ کسی نہ کسی اندراج سے واپس جوڑا جا سکنا چاہیے؛ واپس نہ جوڑا جا سکے، تو سچ کہیں کہ کتاب میں نہیں لکھا، عام فہم فیصلہ دے سکتے ہیں مگر وہ ظاہر کریں کہ یہ عام فہم ہے، کتاب کا مواد نہیں۔ یادداشت سے اعداد، DOI، یا قانونی شقوں کے نمبر مت بھریں۔

کتاب جو واپس ملتا ہے اسے چار چیزوں میں تقسیم کرتی ہے: عمر، وقت اور توانائی، پیسہ، ذاتی آزادی۔ **چاروں الگ الگ شمار ہوتے ہیں، آپس میں تبدیل نہیں ہوتے** — "کل اموات میں 12% کمی" اور "سالانہ 500 یوآن بچت" ایک ہی پیمانے پر نہیں۔

## قدم 0: پہلے دیکھیں کیا فوراً رکنا چاہیے

- **جاری ہنگامی طبی حالت** (گرنے سے سانس رک جانا، شدید خون بہنا، آگ، ڈوبنا، بجلی کا جھٹکا، زہر، فالج یا دل کے دورے کی علامات): پہلے 120 / 119 کال کرنے اور موقع پر پہلا عمل کہیں، ماخذ سیکشن 13، پہلے لاگت-اثر مت بیان کریں۔
- **خودکشی کے خیالات، جینے کی خواہش نہ ہونا**: پہلے قومی نفسیاتی امداد ہاٹ لائن 12356 دیں، پھر سیکشن 1 اور 29 کے اندراجات کے مطابق کہیں، نصیحت کرنے والا تجزیہ نہ کریں، مقاصد کا جائزہ نہ لیں۔
- **جاری قانونی عمل** (summons پہلے ہی مل چکا، پہلے ہی حراست میں ہے، پہلے ہی مقدمہ چل رہا ہے): پہلے سیکشن 8 کے متعلقہ اندراج کی طرف اشارہ کریں، اور واضح کریں کہ کتاب صرف عمومی پیمانہ دیتی ہے، انفرادی کیس کے لیے وکیل تلاش کریں۔
- دیگر صورتوں میں، نیچے کے قدموں پر عمل کریں۔

## قدم 1: مرکزی متن حاصل کریں

**مقامی**: موجودہ ڈائریکٹری یا اوپری ڈائریکٹری میں `README.md` اور `book/01-不要早死.md` موجود ہیں، تو یہ مقامی موڈ ہے، براہ راست پڑھیں۔

**ریموٹ**: نہیں ہے تو ابھی لائیں۔ پوری کتاب 1.3 MB، shallow clone سب سے آسان، بعد کے تمام کمانڈز ویسے ہی استعمال ہوتے ہیں:

```bash
git clone --depth 1 https://github.com/eternity4719/HowToLiveBetter.git "${TMPDIR:-/tmp}/hltb"
```

git استعمال نہ ہو سکے تو فائل بہ فائل لائیں (فائل نام میں چینی براہ راست لکھ دیں):

```bash
curl -fsSL --compressed "https://raw.githubusercontent.com/eternity4719/HowToLiveBetter/main/book/02-不要慢慢死.md"
```

یہ دونوں نہ چلیں، تو مرکزی متن نہیں مل سکتا، صارف کو ایمانداری سے بتائیں، یادداشت سے کتاب کا مواد دوبارہ نہ بیان کریں۔

## قدم 2: سیکشن تک پہنچیں

پہلے 1 سے 3 سیکشن منتخب کریں: ریپو روٹ کے `README.md` میں "یہ کتاب کس سوال کا جواب دینا چاہتی ہے" ٹیبل پڑھیں (ایک سیکشن ایک قطار، یہ بتاتا ہے کہ یہ سیکشن کس سوال کا جواب دیتا ہے، اور `book/` میں متعلقہ فائل نام بھی دیتی ہے)، صارف کے سوال سے مطابقت دیں۔ سیکشنز کا اضافہ/حذف اسی ٹیبل میں ظاہر ہوتا ہے، یہاں الگ فہرست نہیں رکھی۔

سیکشن فائلز `book/` میں ہیں، فائل نام میں سیکشن نمبر اور نام شامل ہیں، `ls book/` سے بھی سب دیکھ سکتے ہیں۔

طویل پڑھائیاں `docs/` میں: کیا شادی کے قابل ہے، گھریلی ہنگامی کٹ، پلیٹ فارم چلانے کے لیے کون سے لائسنس، اجنبی شخص مشکل میں ہو تو رکیں یا نہیں۔

## قدم 3: اندراجات نکالیں

سیکشن فائلز میں سب سے بڑی 110 KB ہے، پوری نہ پڑھیں، کلیدی الفاظ سے نکالیں۔ Grep / Read جیسے آلات ہوں تو استعمال کریں، صرف shell ہو تو کمانڈ استعمال کریں:

```bash
grep -rn '^### ' book/ | grep -E 'کلیدیلفظ1|کلیدیلفظ2'        # پہلے دیکھیں کون سے اندراج کے عنوان ہیں
grep -rn -B2 -A8 'کلیدیلفظ' book/08-别把自己搭进去.md        # متن میں تلاش کریں، سیاق و سباق کے ساتھ
sed -n '/^### 16\. /,/^### 17\. /p' book/08-别把自己搭进去.md  # اندراج نمبر سے پورا اندراج نکالیں
```

**نکالے گئے اندراج کو مکمل پڑھیں**، خاص طور پر "نوٹ" کالم — قابل اطلاق گروہ، تنازعات، استثنائیات سب وہیں لکھے ہیں، صرف عنوان پڑھنے سے شرائط گم ہو جائیں گی۔

ایک اندراج اس طرح نظر آتا ہے:

```markdown
### 5. گھر کا معمولی نمک کم سوڈیم نمک (پوٹاشیم نمک) سے بدل دیں
<!-- 成本标签: 钱=少 时间=少 毅力=否 收益=中 口径=死亡率 -->
- لاگت: ہر تھیلی کچھ یوآن مہنگی
- آسان الفاظ میں: ……موت کا امکان تقریباً 12% کم……
- فائدہ: فالج 14% کم، کاردیو ویسکیولر واقعات 13% کم، کل اموات 12% کم
- ثبوت کا درجہ: A
- ماخذ: Neal B, et al. (2021). NEJM. https://doi.org/10.1056/NEJMoa2105675
- نوٹ: متنازعہ۔ گردے کی کمی، پوٹاشیم بچانے والی diuretics لینے والے استعمال نہ کریں。……
```

HTML کمنٹ کی وہ لائن machine-readable cost tag کے لیے ہے: پیسہ 0/少/多، وقت 少/中/多، ارادہ 否/些/是، فائدہ 大/中/小، میٹرک 死亡率/金钱/时间/自由۔

## قدم 4: ترتیب دیں

ترتیب کتاب کے الگورتھم کے مطابق دیں، احساس سے نہیں:

1. درجے کا الگورتھم ریپو روٹ کے `index.html` کو مستند سمجھیں، یادداشت سے نہ لکھیں، وہاں وہ دو لائنیں نکال کر اسی کے مطابق حساب کریں:

   ```bash
   grep -n 'COST_W = \|e\.ratio = ' index.html
   ```

   پہلی لائن تینوں costs کے ہر درجے کا weight ہے، cost score = پیسہ + وقت + ارادہ تینوں کا جمع؛ دوسری لائن فائدے کے حجم کو cost score کے ساتھ ملا کر "انتہائی اعلیٰ / اعلیٰ / معمولی" میں کیسے رکھتی ہے۔
2. صرف curl سے متن لایا، `index.html` ہاتھ میں نہیں، تو لاگت-اثر درجہ مت دیں، فائدے کا حجم اور تینوں cost tags ایسے ہی درج کریں، صارف خود اندازہ لگائے۔
3. پہلے لاگت-اثر کے مطابق، ایک درجے میں پھر ثبوت کے درجے A > B > C، پھر صارف کی صورتحال سے مطابقت کے مطابق۔
4. **مختلف میٹرکس کے درمیان ترتیب نہیں**۔ پیسہ والے اور عمر والے الگ الگ فہرست بنائیں، ہر ایک اپنی ترتیب۔
5. "معمولی" کا مطلب نہ کرنا نہیں، صرف اتنا ہے کہ وہ لاگت صارف خود اندازہ لگائے۔ لاگت-اثر مصنف کا فیصلہ ہے، کتاب کے اپنے معیار کے مطابق صرف C درجہ، ثبوت کے درجے سے الگ بات۔

## قدم 5: جواب کیسے لکھیں

ترتیب دینے کے بعد اس ڈھانچے پر لکھیں:

1. **ایک جملے کا نتیجہ**: یہ بات قابل ہے یا نہیں، کرنی چاہیے یا نہیں، پہلا قدم کیا ہے۔
2. **پہلے یہ کچھ اندراجات کریں** (3 سے 7، اوپر کی ترتیب کے مطابق)۔ ہر ایک میں ایک سے تین قطاریں: عمل (فعل سے شروع)، کیا خرچ ہوتا ہے، کیا واپس ملتا ہے، ثبوت کا درجہ، ماخذ "سیکشن 8، اندراج 17 (قرض کا کام اور ضمانت)" کے طور پر، قوسین کا لفظ اندراج کے عنوان سے، صارف خود ڈھونڈ سکے۔
3. **مت کریں / کرنے کی ضرورت نہیں**: کتاب میں واضح طور پر ناقابل یا برعکس ثبوت والے، الگ سے فہرست کریں۔
4. **کتاب میں نہیں لکھا**: ایمانداری سے کہیں، عام فہم کو کتاب کا مواد بنا کر پیش نہ کریں۔
5. ضرورت ہو تو دوبارہ جانچنے کا نقطہ شامل کریں: کب واپس دیکھیں، یا کون سا اشارہ ظاہر ہو تو فیصلہ بدلے۔

لکھتے وقت ان باتوں پر قائم رہیں:

- **کس پر پڑتا ہے واضح کریں**۔ کتاب فائدہ پانے والوں کو چار درجوں میں تقسیم کرتی ہے، خود تک واپس آنے کے امکان کے مطابق اعلیٰ سے کم تک: ① آپ خود؛ ② شریکِ حیات اور فوری خاندان؛ ③ دوست، ساتھی، اور دیگر رشتہ دار؛ ④ اجنبی۔ درجہ ④ (اجنبی کو بچانا، ضامن بننا، کسی کے لیے رقم منتقل کرنا) لکھتے وقت خطرے کی سطح اور فائدہ دونوں ساتھ لکھیں: بلیک میل، کیس میں پھنسنا، انتقام، صرف فائدہ نہ لکھیں، اور نہ ہی سب کو یکساں "مت کریں" لکھیں۔
- **"قانون آپ کا ساتھ دیتا ہے" والی باتوں میں عمل کی لاگت بھی ساتھ دیں**۔ صرف نتیجہ کہنا، عمل کو چھوڑنا، جیتنے کی شرح کو فائدہ بنانے کے برابر ہے۔ بتائیں کہ مقدمہ کرنا پڑے گا یا نہیں، تقریباً کتنا عرصہ (پہلی عدالت کا عام عمل 6 مہینے سے شروع، بڑھایا جا سکتا ہے، خلاصہ عمل 3 مہینے)، وکیل کی فیس کون دے گا (وکیل کی فیس litigation costs میں شامل نہیں، ہارنے والا ادا نہیں کرتا)۔
- **اعداد اندراج سے ایسے ہی نقل کریں**، ایک بھی تبدیل نہ کریں۔ اندراج میں confidence interval، آبادی، سال لکھے ہیں تو ساتھ رکھیں؛ HR، RR، OR جیسی شکلوں کے ساتھ "تقریباً 28% کم" کا ترجمہ وہیں کر دیں، اصل قدر نہ مٹائیں۔ اندراج میں نہیں لکھے اعداد، علامات، میکانزم کی تشریح یکا یک نہ شامل کریں۔
- **روزمرہ کی زبان**: پیشہ ورانہ تربیت نہ رکھنے والا بالغ ایک بار پڑھ کر سمجھ لے، ایسے لکھیں۔ پیشہ ورانہ اصطلاح وہیں ایک جملے میں روزمرہ کی زبان میں وضاحت کر دیں، قانونی شق کو "کیا نتائج برداشت کرنا پڑیں گے، کیا کرنا چاہیے" تک لے آئیں۔ ماخذ کالم ایسے ہی دیں، تاکہ تصدیق ہو سکے۔
- **آواز متوازن**، نصیحت نہ کریں، exclamations استعمال نہ کریں، simplified Chinese (اصل چینی نسخے میں؛ اردو ترجمہ میں مناسب اردو)。صارف مشورے پر عمل نہ کرے تو اس کا اپنا معاملہ ہے، پیچھے نہ پڑیں۔
- **پالیسیاں بدلتی ہیں**: سیکشن 7، 19، 21، 24، 31، 32 میں وہ رقم، میعادیں، فہرستیں، متن میں cutoff تاریخ لکھی ہے، جواب میں تاریخ لائیں اور صارف کو باور کرائیں کہ سرکاری ذرائع سے خود تصدیق کرے۔
- "متنازعہ" نشان والے اندراج میں برعکس ثبوت بھی ایک جملے میں کہیں؛ "TODO تصدیق کے لیے" والے کو نتیجہ کے طور پر استعمال نہ کریں۔
- Zhihu، WeChat Official Accounts، Sohu جیسی ثانوی paraphrases کا حوالہ نہ دیں، صرف اندراج کے "ماخذ" کالم میں موجود لنکس دیں۔
